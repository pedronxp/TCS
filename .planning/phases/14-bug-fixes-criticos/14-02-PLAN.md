## Goal

O banner "Sem conexão" não deve sobrepor o conteúdo da tela. Headers devem respeitar o safe area inset do dispositivo.

## Root Causes

### Bug banner offline
- `ConnectivityBanner` usa `position: 'absolute'` com `zIndex: 9999` — flutua sobre o conteúdo
- Quando offline, o banner fica visível indefinidamente, bloqueando visualmente parte do conteúdo scrollável
- Fix: mover o banner para o BOTTOM da tela (toast-style) para não sobrepor o header/conteúdo principal

### Bug responsividade
- Muitas telas usam `paddingTop: 60` fixo no header, o que é insuficiente em dispositivos com notch/status bar grande
- Deve usar `useSafeAreaInsets().top` para calcular o paddingTop correto

## Tasks

### Task 1 — ConnectivityBanner: mover para bottom
**File**: `components/ConnectivityBanner.tsx`

Remover a lógica de `pillTop` baseada no header. Posicionar o pill na parte **inferior** da tela:
```ts
const pillBottom = insets.bottom + 80; // acima da bottom nav
```
Mudar o `hiddenOffset` para animar de baixo para cima:
```ts
const hiddenOffset = PILL_HEIGHT + pillBottom + 16; // off-screen bottom
```
Mudar a propriedade do style de `top` para `bottom`.

### Task 2 — Responsividade: corrigir paddingTop nos headers
**Files** com `paddingTop: 60` ou similar fixo:
- `app/(panel)/inspecoes/resultado.tsx` (styles.header)
- `app/(panel)/inspecoes/relatorio.tsx` (styles.header)
- `app/(panel)/inspecoes/[id].tsx` (styles.header)
- `app/(panel)/inspecoes/wizard.tsx` (styles.header)
- `app/(panel)/dashboard.tsx` (styles.header)

Para cada arquivo, usar `useSafeAreaInsets()` e calcular:
```ts
const insets = useSafeAreaInsets();
// No style inline: paddingTop: insets.top + 16
```
