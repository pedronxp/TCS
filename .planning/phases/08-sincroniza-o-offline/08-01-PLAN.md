  <action>
O bug: `prevConnected = useRef(true)` faz com que na primeira renderização, se `isOnlineReal` já for `true`, a condição `!prevConnected.current` seja `false` e o sync não dispara. O `startAppStateSyncListener()` com debounce de 3s cobre parcialmente esse caso (dispara quando o AppState muda para `active`), mas há uma janela onde o app já está `active` e conectado sem sync.

Correção em app/(panel)/_layout.tsx:

1. Alterar `prevConnected` para inicializar como `false` em vez de `true`:
   ```typescript
   const prevConnected = useRef(false);
   ```
   Isso faz com que na primeira execução do useEffect, se `isOnlineReal=true`, a condição `isOnlineReal && !prevConnected.current` seja verdadeira e o sync dispare imediatamente.

2. Adicionar comentário explicativo logo acima do useRef:
   ```typescript
   // Inicializar como false para garantir sync imediato no mount quando já conectado.
   // Se isOnlineReal=true na primeira renderização, dispara syncPendentes() imediatamente.
   // O guard _syncInProgress em SyncService.ts garante idempotência se AppState também disparar.
   const prevConnected = useRef(false);
   ```

3. Não alterar mais nada no arquivo. O restante da lógica (watcher de reconexão, background task, AppState listener) está correto.

Verificar que o lint passa após a mudança.

A pesquisa identificou um edge case documentado mas não tratado: se o upload para o Supabase Storage for bem-sucedido mas o app morrer antes de `db.runSync(UPDATE vistorias_offline SET foto_url...)` em processarImagensVistoria(), o arquivo ficará órfão no Storage e a vistoria continuará com `file://` no SQLite. No próximo retry, um novo path com novo `Date.now()` é gerado, então não há conflito de caminho, mas pode acumular arquivos órfãos.

Ação:
1. Adicionar um comentário JSDoc em services/StorageService.ts, logo acima de `uploadImageFromLocalUri`, documentando este comportamento:

```typescript
/**
 * ...docblock existente...
 *
 * @note COMPORTAMENTO DE RETRY: O remotePath inclui Date.now(), então cada
 * tentativa de upload usa um caminho único. Se o upload for bem-sucedido mas
 * o app morrer antes de persistir a URL pública no SQLite, o arquivo
 * permanecerá no Storage sem referência (arquivo órfão). O retry seguinte
 * fará upload para um novo path sem conflito. Para limpeza de órfãos,
 * seria necessário um job periódico no Supabase (out of scope para SYNC-01).
 */
```

2. Não alterar a lógica de upload. O comportamento atual (upsert: false + Date.now() no path) é aceitável para SYNC-01.
