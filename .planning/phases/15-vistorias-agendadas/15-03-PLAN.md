## Goal

Agente pode tocar num agendamento para ver detalhes. Supervisor/Admin podem marcar como concluído ou cancelar. Badge numérico no ícone do header mostra quantos agendamentos pendentes existem.

## Tasks

### Task 1 — Tela de detalhe (app/(panel)/agendamentos/[id].tsx)

Exibe todos os campos do agendamento em modo leitura:
- Cabeçalho: título + badge de status
- Data e hora formatada (extenso pt-BR)
- Endereço + município
- Agente atribuído (nome)
- Observações
- Criado por + data de criação

Para `supervisor`/`admin`/`master_admin`: dois botões de ação no rodapé:
- "Marcar como Concluído" (verde) → `updateAgendamentoStatus(id, 'concluido')` + upsert Supabase
- "Cancelar Agendamento" (vermelho, com confirmação) → `updateAgendamentoStatus(id, 'cancelado')` + upsert Supabase

Para `agent`: somente visualização, sem botões de ação.

### Task 2 — Badge numérico no ícone do header

No header de todas as telas (dashboard, admin, supervisor, master):

```tsx
// Badge sobre o ícone de calendário
{pendingCount > 0 && (
  <View style={styles.badge}>
    <Text style={styles.badgeText}>{pendingCount > 9 ? '9+' : pendingCount}</Text>
  </View>
)}
```

`pendingCount` = número de agendamentos com status='pendente' buscado localmente do SQLite na montagem do componente.

### Task 3 — Sincronização de status de volta ao Supabase

Quando agendamento é concluído/cancelado offline:
- Salva localmente via `updateAgendamentoStatus()`
- Adiciona o id em uma fila simples (`agendamentos_pendentes_sync`) no SQLite
- Quando vai online, faz upsert do status no Supabase

(Implementação simples: adicionar campo `sincronizado INTEGER DEFAULT 0` já existe no schema do 15-01. Na reconexão, busca agendamentos onde `sincronizado = 0` e faz upsert.)
