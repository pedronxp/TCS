## 1. Criar `assets/formularios/risco_estrutural_completo_v1.json`

Criar o arquivo com o conteúdo exato abaixo. Não inventar novos campos — seguir estritamente o formato de `risco_estrutural_v1.json`.

Regras de mapeamento dos JSONs externos para o formato nativo:
- Cada elemento (foundation, structure, roof, masonry, floor, stairs, wall, facade, drainage, electrical) vira uma `fase`.
- Cada fase tem exatamente 4 perguntas: `estado`, `gravidade`, `extensao`, `ativa`.
- Os pesos de cada elemento vêm dos JSONs externos: form1 (foundation=1.5, structure=1.5, roof=0.9, masonry=1.0), form2 (floor=0.8, stairs=1.0, wall=1.4, facade=0.8, drainage=1.1, electrical=0.9).
- Pontuação das opções de estado: bom=0, regular=2, ruim=4, pessimo=6 (conforme `state` no JSON externo).
- Pontuação das opções de gravidade: nenhuma=0, leve=1, moderada=3, severa=5 (conforme `severity`).
- Pontuação das opções de extensão: pontual=1, setorial=2, generalizada=4 (conforme `extension`).
- Pontuação das opções de ativa: nao=0, sim=2 (conforme `activity`).
- `imagemLocal` para fundação: `fund_bom`, `fund_regular`, `fund_ruim`, `fund_pessimo` (imagens específicas existentes no FORM_IMAGES do wizard).
- `imagemLocal` para os demais 9 elementos: usar `est_bom`, `est_regular`, `est_ruim`, `est_pessimo` como fallback genérico (todas presentes no FORM_IMAGES).
- `imagemLocal` de gravidade: `grav_nenhuma`, `grav_leve`, `grav_moderada`, `grav_severa` (todas presentes).
- `imagemLocal` de extensão: `ext_pontual`, `ext_setorial`, `ext_generalizada` (todas presentes).
- `imagemLocal` de ativa: `opcao_nao`, `opcao_sim` (ambas presentes).
