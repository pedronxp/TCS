# Plan 07-01: Auditoria e Correção dos JSONs Built-in

**Phase:** 07 — Formulários + Classificação de Risco
**Wave:** 1 of 3
**Req IDs:** FORM-01
**Goal:** Garantir que todos os 4 JSONs built-in usam `classificacao.limites[]` consistente com o `nivelMap` do wizard e que a chave dos assets no mapa `ASSETS` inclui a versão correta

## Context

O wizard carrega JSONs via:

```typescript
// wizard.tsx linha 21-26
const ASSETS: Record<string, any> = {
  'estrutural_v1': require('../../../assets/formularios/estrutural.json'),
  'deslizamento_campo_v1': require('../../../assets/formularios/deslizamento_campo.json'),
  'estrutural_avancado_v1': require('../../../assets/formularios/estrutural_avancado.json'),
  'inundacao_v1': require('../../../assets/formularios/inundacao.json'),
};
```

A lookup usa `params.formularioId` diretamente como chave — portanto o `"id"` do JSON **deve** coincidir exatamente com a chave do mapa (ex: `"id": "estrutural_v1"`).

O `calcularNivelRisco()` (linha 199–233) só suporta `tipoCalculo: "soma_total"` com `classificacao.limites[]`. O JSON `estrutural_avancado.json` usa `tipoCalculo: "pontuacao_por_item"` com `regrasGlobal` — esse é o único caso fora do padrão que precisa ser documentado e protegido.

**nivelMap suportado pelo wizard:**

```typescript
const nivelMap: Record<string, string> = {
  sem_risco: 'r1', baixo: 'r1',
  medio: 'r2', medio_baixo: 'r2',
  alto: 'r3', medio_alto: 'r3',
  iminente: 'r4', critico: 'r4',
};
```

**Estado atual dos 4 JSONs (resultado da auditoria de leitura):**

| JSON | id no arquivo | chave no ASSETS | tipoCalculo | limites[] | compatível? |
|------|--------------|-----------------|-------------|-----------|------------|
| estrutural.json | `estrutural_v1` | `estrutural_v1` | soma_total | 4 entradas (sem_risco/medio/alto/iminente) | OK |
| deslizamento_campo.json | `deslizamento_campo_v1` | `deslizamento_campo_v1` | soma_total | 4 entradas (baixo/medio/alto/iminente) | OK |
| inundacao.json | `inundacao_v1` | `inundacao_v1` | soma_total | 4 entradas (baixo/medio/alto/iminente) | OK |
| estrutural_avancado.json | `estrutural_avancado_v1` | `estrutural_avancado_v1` | **pontuacao_por_item** | usa regrasGlobal, **sem limites[]** | PROBLEMA |

O `estrutural_avancado` não tem `classificacao.limites[]` — quando carregado, o wizard faz `setLimites(json?.classificacao?.limites || [])` que resulta em array vazio, fazendo fallback hardcoded (0-24=r1, 25-49=r2, 50-74=r3, ≥75=r4). Isso é incorreto para esse formulário.

**Arquivos relevantes:**
- `assets/formularios/estrutural_avancado.json` — precisa de `classificacao.limites[]` adicionado
- `assets/formularios/deslizamento_campo.json` — limites usam decimais (max: 1.0, 3.0, 5.0), verificar se funciona com pontuação inteira somada
- `app/(panel)/inspecoes/wizard.tsx` — `draftKey` não inclui versão, pode servir draft de versão antiga

## Tasks

### Task 1: Adicionar `classificacao.limites[]` ao estrutural_avancado.json

**File:** `assets/formularios/estrutural_avancado.json`

**What:** Adicionar array `limites` dentro de `classificacao`, derivado das `regrasGlobal` existentes, de modo que o wizard possa calcular o risco via `soma_total` como fallback enquanto `pontuacao_por_item` não é suportado. Incrementar `versao` de 1 para 2.

**Why:** Sem `limites[]`, o wizard usa fallback hardcoded que ignora completamente os critérios calibrados do formulário avançado. Com `limites[]` derivado das regras existentes, o resultado fica ao menos razoável. O campo `tipoCalculo` permanece `"pontuacao_por_item"` para futura implementação.

O mapeamento das regrasGlobal para limites:
- `maxMinimo: 6` → `medio` → limites max 5 = baixo, max 10 = medio
- `maxMinimo: 11` → `alto` → limites max 14 = alto
- `maxMinimo: 15` → `iminente` → limites max 9999 = iminente

Adicionar dentro do objeto `"classificacao"` (junto ao bloco existente de `regrasGlobal`):

```json
"limites": [
  { "max": 5,    "nivel": "baixo",    "label": "R1 — BAIXO — Sem intervenção imediata", "cor": "verde" },
  { "max": 10,   "nivel": "medio",    "label": "R2 — MÉDIO — Vistoria técnica necessária", "cor": "amarelo" },
  { "max": 14,   "nivel": "alto",     "label": "R3 — ALTO — Laudo de engenheiro obrigatório", "cor": "laranja" },
  { "max": 9999, "nivel": "iminente", "label": "R4 — CRÍTICO — Interdição imediata", "cor": "vermelho" }
]
```

Alterar também `"versao": 1` para `"versao": 2`.

### Task 2: Corrigir `draftKey` no wizard para incluir versão do formulário

**File:** `app/(panel)/inspecoes/wizard.tsx`

**What:** Alterar a linha 65:

```typescript
// Antes (linha 65):
const draftKey = `@draft_wizard_${params.formularioId}`;

// Depois:
const draftKey = `@draft_wizard_${params.formularioId}_v${params.formularioVersao || '1'}`;
```

**Why:** Sem a versão na chave, um agente que atualizou o formulário de `estrutural_avancado_v1` versão 1 para versão 2 teria um rascunho carregado com perguntas de uma versão que não existe mais. Com a versão na chave, o rascunho antigo simplesmente não é encontrado e um novo rascunho limpo começa.

Não alterar nenhuma outra parte do wizard neste plano — o banner de risco (FORM-02) é o plano 07-02.

### Task 3: Adicionar teste de auditoria dos JSONs

**File:** `utils/__tests__/formularios.test.ts` (arquivo novo)

**What:** Criar suite de testes que valida estrutura dos 4 JSONs built-in:

```typescript
/**
 * Testes de auditoria dos JSONs de formulários built-in.
 * Garante que wizard.tsx pode calcular risco em todos eles.
 */

const estrutural = require('../../assets/formularios/estrutural.json');
const deslizamento = require('../../assets/formularios/deslizamento_campo.json');
const estruturalAvancado = require('../../assets/formularios/estrutural_avancado.json');
const inundacao = require('../../assets/formularios/inundacao.json');

const FORMULARIOS = [estrutural, deslizamento, estruturalAvancado, inundacao];
const NIVEL_VALIDOS = ['sem_risco', 'baixo', 'medio', 'medio_baixo', 'alto', 'medio_alto', 'iminente', 'critico'];

describe('JSONs built-in — estrutura base', () => {
  FORMULARIOS.forEach(f => {
    it(`${f.id} tem id, versao, fases e tipoCalculo`, () => {
      expect(f.id).toBeTruthy();
      expect(f.versao).toBeGreaterThanOrEqual(1);
      expect(Array.isArray(f.fases)).toBe(true);
      expect(f.fases.length).toBeGreaterThan(0);
      expect(f.tipoCalculo).toBeTruthy();
    });
  });
});

describe('JSONs built-in — classificacao.limites[]', () => {
  FORMULARIOS.forEach(f => {
    it(`${f.id} tem classificacao.limites[] não-vazio`, () => {
      expect(Array.isArray(f.classificacao?.limites)).toBe(true);
      expect(f.classificacao.limites.length).toBeGreaterThan(0);
    });

    it(`${f.id} limites usam nivel compatível com nivelMap`, () => {
      f.classificacao.limites.forEach((l: any) => {
        expect(NIVEL_VALIDOS).toContain(l.nivel);
      });
    });

    it(`${f.id} limites têm max numérico crescente`, () => {
      const maxes = f.classificacao.limites.map((l: any) => l.max);
      for (let i = 1; i < maxes.length; i++) {
        expect(maxes[i]).toBeGreaterThan(maxes[i - 1]);
      }
    });
  });
});

describe('JSONs built-in — perguntas com pesoRisco', () => {
  FORMULARIOS.forEach(f => {
    it(`${f.id} todas opções têm pesoRisco numérico`, () => {
      for (const fase of f.fases) {
        for (const pergunta of fase.perguntas || []) {
          for (const opcao of pergunta.opcoes || []) {
            expect(typeof opcao.pesoRisco).toBe('number');
          }
        }
      }
    });
  });
});
```

**Why:** Garante que qualquer edição futura nos JSONs não quebra a compatibilidade com o wizard sem alertar o executor.
